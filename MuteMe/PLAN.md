# MuteMe 项目计划

## 项目概述

MuteMe 是一个 Windows 后台工具，用于监视用户指定的进程列表。当列表中的进程切换到后台时自动静音，切换到前台时自动恢复音量。关闭窗口时最小化到系统托盘。

## 核心功能

### 1. 进程列表管理

- **输入进程名**：主界面提供文本输入框，用户可输入进程名（如 `chrome`、`WeChat.exe`）并添加到监视列表
- **列表展示**：以 ListBox/ListView 展示当前监视的进程列表
- **删除进程**：选中列表项后可删除
- **持久化存储**：进程列表保存到本地配置文件（JSON），启动时自动加载

### 2. 自动静音/恢复

- **前台检测**：定时轮询（如每 500ms）当前前台窗口所属进程
- **后台静音**：当监视列表中的进程不在前台时，对该进程的所有音频会话静音
- **前台恢复**：当监视列表中的进程回到前台时，恢复该进程的音量
- **延迟机制**：用户可配置延迟时间（秒），进程切到后台后等待指定时间再静音，避免短暂切换误触

### 3. 延迟时间设置

- 主界面提供 NumericUpDown 控件设置延迟秒数（0-60 秒，默认 3 秒）
- 延迟时间同样持久化到配置文件

### 4. 系统托盘

- **关闭到托盘**：点击窗口关闭按钮时，隐藏主界面，显示托盘图标
- **托盘菜单**：
  - 双击托盘图标：显示主界面
  - 右键菜单：
    - 显示主窗口
    - 退出程序（真正退出）
- **托盘图标**：使用 NotifyIcon 组件

## 技术方案

### 音频控制

使用 Windows Core Audio API (`IAudioSessionManager2`) 按进程控制音量：

- 枚举所有音频会话 (`IAudioSessionEnumerator`)
- 通过会话的进程 ID 匹配目标进程
- 调用 `ISimpleAudioVolume.SetMute(true/false)` 实现静音/恢复

需要 COM 互操作，或使用 NuGet 包 `NAudio` 简化音频 API 调用。

### 前台窗口检测

- 使用 `GetForegroundWindow` Win32 API 获取当前前台窗口句柄
- 使用 `GetWindowThreadProcessId` 获取窗口对应的进程 ID
- 与进程名列表对比判断是否需要静音/恢复

### 定时轮询

- 使用 `System.Windows.Forms.Timer`，间隔 500ms
- 每次触发时：
  1. 获取前台进程名
  2. 遍历监视列表中的进程
  3. 对不在前台的目标进程启动/继续延迟计时
  4. 延迟到期后执行静音
  5. 对回到前台的目标进程立即恢复音量并取消延迟计时

### 配置存储

- 文件路径：`%APPDATA%/MuteMe/config.json`
- 格式：

```json
{
  "processNames": ["chrome", "WeChat.exe"],
  "delaySeconds": 3
}
```

### 系统托盘

- 使用 `NotifyIcon` 组件
- 拦截 `FormClosing` 事件，设置 `e.Cancel = true` 并 `Hide()` 窗口
- 提供"退出"菜单项调用 `Application.Exit()`

## 开发步骤

1. **界面搭建**：完成主界面布局（输入框、列表、延迟设置、状态显示）
2. **进程列表管理**：实现添加、删除、持久化存储
3. **系统托盘**：实现关闭到托盘、托盘菜单、双击恢复
4. **音频控制**：集成 NAudio，实现按进程静音/恢复
5. **前台检测**：实现前台窗口进程检测
6. **自动静音逻辑**：整合定时器、延迟机制、静音/恢复联动
7. **测试与优化**：测试各场景，优化响应速度和稳定性

## 依赖

- **NAudio**：Windows 音频 API 封装，用于进程级音量控制
- **.NET 10**：目标框架
- **WinForms**：UI 框架
